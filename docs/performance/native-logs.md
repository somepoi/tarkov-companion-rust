# Native log transport and shared interpretation

Rust owns read-only filesystem access, folder discovery, notifications, scoped paths and byte cursors. The incumbent pure TypeScript interpreter is shared by Electron and a dedicated native frontend worker. Its timestamp/session/quest/flea grammar has not been independently rewritten in Rust. Electron compatibility exports retain existing script/import paths. This boundary preserves working interpretation while removing native log I/O and parsing from the React thread.

The native bridge pulls at most 256 KiB per IPC operation and waits for worker acknowledgement before reading more. Filesystem events are coalesced into a dirty signal; stable idle watching does not run a periodic tailing interval. Stateful UTF-8 decoding preserves character boundaries. Each read rechecks the selected directory scope. Creation time, length, a small prefix and the last read boundary detect ordinary truncation/replacement; a replacement resets the session timeline and replays available files as history. This is not cryptographic detection of arbitrary in-place edits to an entire log.

Application logs precede notifications so the shared interpreter can attribute notification times to mode/profile timelines. Initial historical events are buffered until the initial pass drains, then filtered against the latest observed profile and reset period before automatic application. Historical line boundaries remain attached to entries completed by a later live chunk. Unknown-mode quest events cannot update either progression store; the manual backfill review reports excluded events. Native known-profile markers are stored separately per game mode to avoid treating PvE/PvP switching as a wipe. Only the latest historical profile/version observations become persisted identity markers.

Backfill and Stats use a separate bounded stream, the shared current-profile/reset reducer and the existing review UI. A failed read is cancelled; partial counts are not returned as a completed backfill. Limits are 10,000 session folders, 50,000 files, 200,000 interpreted events per historical pass and four million buffered UTF-16 code units per parser entry. Limit/encoding/worker errors are visible rather than silently discarding data. Worker parsing failures require reconnecting the selected folder; a stopped worker requires restarting the app.

Installation discovery reads bounded launcher/Steam configuration files and extracts installation path fields. Launcher credential fields are not retained or transmitted. Benchmark mode bypasses discovery and game-folder access. No game process is opened, no memory/traffic is read and no game files are modified.

Root removal/recreation is now source-implemented by watching the selected root recursively and its nearest existing ancestor nonrecursively, searching at most 32 ancestors. Notifications outside the selected subtree/ancestor chain are filtered, with Windows component case normalization and canonical-anchor aliases for missing suffixes. Canonical root/creation changes reset the transport epoch, live cursor and pending history. Parser/session changes also revoke filename-position cleanup authority. Paused and benchmark modes start no watcher; paused history reads retain the resolved root. There is no idle timer.

Watcher failures rearm at most twice within a 60-second window; the third failure stops watching with an explicit reconnect message. Successful rearming retains a visible warning. Transport failures can retry only on a filesystem notification, including one queued during the failing attempt. Parser/data errors retain explicit reconnect behavior. This is bounded recovery logic, not observed Windows notification parity.

History now offers each session's metadata signature before reading bytes. The signature binds the native canonical root, root/session creation times, parser/application format revision and sorted recognized-file names, lengths, creation and modification times. A worker cache hit is accepted only after Rust rechecks that completed session's signature. Uncached completed sessions are checked before admission and after parsing; changing metadata aborts the pass. The newest session is always read as an uncached byte snapshot; truncation below that snapshot boundary fails explicitly.

The worker keeps an LRU cache of at most 128 completed sessions, 50000 events and four million serialized UTF-16 code units across retained entries. These are logical retention bounds, not a measured process-memory ceiling. Cached values contain raw historical events and one session span; current-profile/reset/finished-quest reductions rerun over all sessions on every request. Cancellation/errors discard the current aggregate. Successfully completed cached sessions may remain for later requests. Cache state lives only in the worker, resets at application/worker restart, and never writes game files or user inventory. Metadata signatures detect ordinary changes, not deliberate same-size/same-time rewriting; no cryptographic log-integrity guarantee is claimed.

Directory enumeration is bounded to 50000 entries per root/session in addition to existing folder/file/event/parser limits. Remaining gates include observed live rotation/truncation/locked-file handling, root removal/recreation and notification casing, current-profile/wipe behavior on real logs, cache hit/cancellation runtime behavior, history cancellation UX and measured resource use. The event-driven design and cache are implementation facts, not measured performance improvements. No real game logs were read during this source/build checkpoint, and no tests were created or run.
