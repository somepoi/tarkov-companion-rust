# Native log transport and shared interpretation

Rust owns read-only filesystem access, folder discovery, notifications, scoped paths and byte cursors. The incumbent pure TypeScript interpreter is shared by Electron and a dedicated native frontend worker. Its timestamp/session/quest/flea grammar has not been independently rewritten in Rust. Electron compatibility exports retain existing script/import paths. This boundary preserves working interpretation while removing native log I/O and parsing from the React thread.

The native bridge pulls at most 256 KiB per IPC operation and waits for worker acknowledgement before reading more. Filesystem events are coalesced into a dirty signal; stable idle watching does not run a periodic tailing interval. Stateful UTF-8 decoding preserves character boundaries. Each read rechecks the selected directory scope. Creation time, length, a small prefix and the last read boundary detect ordinary truncation/replacement; a replacement resets the session timeline and replays available files as history. This is not cryptographic detection of arbitrary in-place edits to an entire log.

Application logs precede notifications so the shared interpreter can attribute notification times to mode/profile timelines. Initial historical events are buffered until the initial pass drains, then filtered against the latest observed profile and reset period before automatic application. Historical line boundaries remain attached to entries completed by a later live chunk. Unknown-mode quest events cannot update either progression store; the manual backfill review reports excluded events. Native known-profile markers are stored separately per game mode to avoid treating PvE/PvP switching as a wipe. Only the latest historical profile/version observations become persisted identity markers.

Backfill and Stats use a separate bounded stream, the shared current-profile/reset reducer and the existing review UI. A failed read is cancelled; partial counts are not returned as a completed backfill. Limits are 10,000 session folders, 50,000 files, 200,000 interpreted events per historical pass and four million buffered UTF-16 code units per parser entry. Limit/encoding/worker errors are visible rather than silently discarding data. Worker parsing failures require reconnecting the selected folder; a stopped worker requires restarting the app.

Installation discovery reads bounded launcher/Steam configuration files and extracts installation path fields. Launcher credential fields are not retained or transmitted. Benchmark mode bypasses discovery and game-folder access. No game process is opened, no memory/traffic is read and no game files are modified.

Remaining gates include observed live rotation/truncation/locked-file handling, root directory removal/recreation, current-profile/wipe behavior on real logs, finished-session caching comparable to Electron's cache, history cancellation UX and measured resource use. The event-driven design is an implementation fact, not a measured performance improvement. No real game logs were read during this source/build checkpoint, and no tests were created or run.
