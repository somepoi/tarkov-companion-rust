# OCR pixel preparation worker

Goal: remove synchronous screenshot preprocessing from the UI thread so the newly added cancellation control can be serviced while preprocessing runs. This addresses the audit's identified main-thread luminance/bicubic/threshold allocation path. It is not a demonstrated scan-latency or memory optimization.

Extract the existing pixel operations without changing arithmetic: bounded screenshot decode, crop coordinates, luminance weights, Keys bicubic enlargement, Otsu/explicit threshold, white padding and PNG output. Keep padding shared with the incumbent Tesseract coordinate conversion. Use a dedicated disposable Vite worker for each admitted read; the existing one-running/one-waiting OCR queue limits concurrency. Transfer only Blob/crop/threshold/scale through the worker message. Page callbacks, AbortSignals, model resources and Tesseract remain outside the preprocessing worker.

Terminate preprocessing on success, reported failure, script/message failure, postMessage failure or cancellation, releasing its canvases/arrays rather than retaining the last image. Preserve pixel/file admission and enlarged-image limits. Page-side generation/signal checks still precede recognition and result publication. A generation-only caller without an AbortSignal discards stale results after preparation completes; Stash Manager cancellation terminates preparation directly. Existing image-only fallback/unknown quantity behavior continues on failure.

Both production targets emit the standalone preparation worker asset (4.19 kB in this build), and existing worker-src policies permit same-origin worker assets. This is build/source evidence; installed WebView2 runtime delivery is not established by compilation. Per-read worker startup overhead, total pipeline latency/memory and OCR-output equivalence remain unmeasured. No speed, accuracy or measured responsiveness gain is claimed; Phase 8 comparison gates remain open.

Verification on 2026-11-01: clean oxlint, TypeScript, Tauri frontend production build, Electron frontend/main/preload production build, embedded native custom-protocol development build (20.99s) and whitespace checks exited 0. Source review compared the moved arithmetic, shared padding/coordinate mapping, queue ownership, serializable message fields and termination/error paths. No tests, fixtures, image processing, screenshots or game workflows were created or run. Installer refresh and runtime worker/cancellation acceptance remain open.
