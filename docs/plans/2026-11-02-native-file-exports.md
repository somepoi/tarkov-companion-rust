# Native save dialogs for progress and inventory reports

Source review of Phase 3/9 export paths found that progress JSON and saved-inventory JSON/CSV still relied on browser anchor downloads. A click is not a completed native file write. Add a Rust-owned save path while keeping the explicit browser/Electron reference fallback.

## Implementation

- The main window requests a native Save As dialog with a bounded suggested name and fixed JSON/CSV kind. The renderer never supplies or receives a destination path. The native service serializes its dialog/write operations and refuses measurement-mode dialogs and searchbar requests.
- Selection grants one process-local two-minute permit bound to destination, format, parent object identity and the existing target's metadata/file identity (or absence). The adapter checks the caller's current-context predicate after selection; cancellation discards the permit without writing. Inventory export checks its profile/mode and component lifetime before the dialog and after it. Once native writing begins it saves that prepared immutable report, not a later live inventory view.
- Native writing requires an exact permit, a nonempty UTF-8 payload up to 20 MiB and the expected progress/inventory JSON envelope or inventory CSV header. Import validation remains separate; these checks are not a complete document-schema or CSV-body validator. Exports cannot be written inside this application's native profile root. Symlinks/reparse points and hard-linked targets are rejected.
- Compare destination/parent identity before writing and immediately before publication. A newly appearing target or changed selected file is rejected at those checks. Create a fresh sibling temporary file, write/flush it, then rename into the selected destination. On failure, clean up only the created temporary file while its parent identity still matches; otherwise retain it and report that fact. No directory recursion, target truncation, permanent-delete fallback or arbitrary-path write command is exposed. Filesystem checks do not constitute an atomic compare-and-swap against another same-user process racing the final rename, nor prove power-loss durability on every filesystem/share.
- The installed dialog dependency uses the Windows common Save dialog with its default overwrite prompt, confirmed by installed source inspection and Microsoft's [common-dialog documentation](https://learn.microsoft.com/en-us/windows/win32/shell/common-file-dialog). Runtime dialog behavior is still unverified; no extra custom overwrite approval flow is added.
- Share the existing Windows identity reader with manual cleanup, preserving its object/reparse/link checks. Existing position-shot recycling is unchanged. Select/write jobs hold the existing native IO lease through their actual blocking work, excluding staged update preparation; cancellation changes memory only.
- Progress export reports saved/cancelled/error, checks its file limit and prevents repeated UI submission while saving. The browser reference reports a download request and delays URL release. Inventory reports preserve CSV formula escaping and restore the UTF-8 BOM after Blob.text decoding; full recovery backup remains a separate workflow.

## Verification and remaining evidence

Clean lint, TypeScript/native frontend, Electron frontend/main/preload, both strict Rust feature variants, formatting, local documentation links and whitespace passed. Final embedded native development build exited 0 in 21.63s after the plain-filename/alternate-stream guard. Independent source-only review found no P1/P2 issue in routing/permit/scope/cancellation/publication or the extracted identity reader.

No tests, simulated filesystem failures, dialogs, application launches, exports or user-profile operations were run. Runtime Save As/cancel/overwrite, Unicode filesystem behavior, disk-full/restart durability and the broader migration gates remain unverified. Release installer not refreshed by this source task.
