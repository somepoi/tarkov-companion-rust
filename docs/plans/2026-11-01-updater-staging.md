# Native updater discovery staging

Goal: prepare the native updater seam while fork-owned public channel/key information is pending. This is the first read-only staging step toward signed updates, not a release/update installation implementation.

Source: [official Tauri updater guide](https://v2.tauri.app/plugin/updater/) and installed tauri-plugin-updater 2.14.1 source. Manifest discovery is not artifact signature verification: the plugin checks the signature when downloading the installer. A discovered candidate is explicitly returned with signatureVerified=false and installable=false. No download/install function or plugin guest permissions are exposed here. Existing desktop update status/check/install routes and updateMode guard remain disabled.

An optional Rust staged-updates feature adds the updater using the project's existing native-TLS transport. The plugin initializes only when a valid compile-time TC_STAGED_UPDATE_ENDPOINT and TC_STAGED_UPDATE_PUBLIC_KEY are present. The key is parsed as base64 Tauri public-key content and a two-line minisign public key; private-key blobs are not accepted. Never pass a private key to either variable. Build-time parsing rejects malformed/private-key-shaped input before option_env can embed the supplied value; diagnostics contain no key text. Runtime validation repeats the public-key parse. Build rerun directives track both public variables. Invalid/missing parameters do not silently select another channel.

Endpoints require HTTPS, a domain, no credentials/query/fragment, bounded length and no loopback IP. GitHub/raw-GitHub endpoints must use somepoi/tarkov-companion-rust paths; there is no original-project fallback. A custom domain's ownership must be established by the release operator before configuring it. Discovery uses the plugin's normal newer-version comparison, a 30-second request timeout and a single in-flight guard. It is main-window-only and disabled in benchmark mode. Config/key input is never accepted from the command caller. The plugin's manifest parsing is upstream code; no custom response-size budget or verified installer download has been added in this step.

Explicit staging UI: build the frontend with VITE_STAGED_UPDATES=1 and the native host with --features custom-protocol,staged-updates (tauri build adds custom-protocol itself). Settings then offers a read-only channel preview. Normal builds exclude that UI and the optional updater dependency. No configured endpoint or signing material is committed. No auto-check timer, automatic install, release workflow publication, updater artifacts or installer execution is enabled.

The Rust notice builder now includes all feature variants, so even optional updater builds retain complete bundled notices. CI compiles the staged feature with strict Clippy and no real endpoint/key. Full signed download/verification, job quiescence before install, installation outcome recovery, signed staging and release acceptance remain open. Public channel/key data was requested separately; no answer has been inferred.

Verification on 2026-11-01: default and staged custom-protocol strict workspace Clippy, frontend production build/type checking, clean oxlint, native builds for staged (29.25s) and normal custom-protocol (28.41s), notice generation (317 Windows-reachable crates/195 license texts), formatting and whitespace checks exited 0. Workflow YAML parsed with Python after the optional Node yaml package was unavailable. Source review traced compile-time key handling, missing/invalid configuration, plugin initialization, main-window/benchmark checks, no guest updater permissions, discovery-only candidate status and disabled production update routes. No tests, key generation, live update check, download, installation, publishing or screenshot workflow were created or run. Installer artifacts were not refreshed.
