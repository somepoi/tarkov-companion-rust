# Measurement profile ownership and completion reporting

Goal: make the isolated performance runner's launch evidence reliable before gathering more release measurements. This is part of Phase 1 tooling, not a completed performance comparison.

Source inspection of Tauri single-instance 2.5.4 shows Windows mutex identity derives from the fixed application identifier. An isolated profile alone does not change that mutex, so a benchmark can hand off to a pre-existing instance. Both fork hosts now omit normal single-instance integration only in their explicit TC_BENCH_DISABLE_INTEGRATIONS=1 mode; ordinary instances keep their previous behavior.

Before native application construction or Electron userData/bootstrap side effects, claim an existing empty absolute profile named profile under the actual OS temporary directory's tc-desktop-baseline-<alphanumeric> directory. Require a bounded regular launch.json whose canonical profile/executable match this process. Reject symlink profile/launch files, reused/nonempty profiles and mismatched launch records. Create an exclusive .benchmark-owner.json marker and flush it; no marker/profile/source file is removed. Tauri caches the claimed path for its later HostState setup rather than claiming it twice. This prevents concurrent/repeated use of the same fresh profile while bypassing singleton integration. This is accidental-misuse isolation, not a security boundary against a hostile process with the same filesystem rights.

The PowerShell sampler records an observed root exit and stops sampling that process tree early. Its completion fields separately record full-window observation, sampling-row count, layout readiness and catalog readiness. A root exit, incomplete window, empty sampling phase or absent layout signal returns failure after preserving the sampling report. Catalog readiness remains a separate qualification for idle comparisons. A failure during process launch may have only the launch record; sampling reports are preserved by the existing finally block once sampling begins. No child/user process is stopped and no profile is deleted by these changes.

These hosts now require the actual measurement launcher contract and fresh profiles; arbitrary hand-written profile overrides are not a supported benchmark shortcut. Fresh profiles do not establish cold OS caches or warm persisted-state behavior. Existing historical raw reports are not rewritten or retroactively relabeled; prior observations that included their own readiness signals are distinct evidence.

The attempted updater-metadata budget follow-up remains open: the installed plugin's configure_client API adjusts request construction, while its check path calls response.json without a body-limit hook. No ineffective HEAD/range preflight or insecure local metadata proxy was added. This finding redirected independent work to the measurement isolation prerequisite.

Verification: staged/default strict Clippy, native embedded builds, clean lint, TypeScript and Electron frontend/main/preload builds passed. The final PowerShell source parsed without execution; source review corrected the normal-loop completion flag placement and covered finally/error paths. No tests, simulated launch/exit cases, profiles, application launches, metrics, screenshots or game workflows were run. Full runtime isolation/completion behavior and performance acceptance remain unverified.
