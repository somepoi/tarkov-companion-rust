# Native searchbar integration

**Goal:** Preserve the incumbent lightweight search/map overlay in an isolated Tauri webview, with show/search/lock/map hotkeys, anchored resize/drag/corner placement, safe navigation and transparent-gap input behavior.

Reuse SearchBarApp/Body and shared desktop channels. Keep lazy content and idle unload. Rust owns one transparent frameless always-on-top taskbar-free window sharing the fork's active WebView data directory. Clamp physical placement to a monitor work area, converting CSS sizes/deltas with the target monitor scale. The glass anchor remains stable while the expanded window flips near screen edges. Persist the private anchor separately from public settings.

Tauri does not offer Electron's forwarded pointer moves while ignoring cursor events. On Windows, the renderer reports bounded rectangles for existing `[data-solid]` elements; a union window region makes transparent gaps absent from the input surface without hooks/polling. Whole-overlay lock uses native ignore-cursor events. The mask follows DOM/layout changes and scaling, and updates only when geometry changes. Preserve visible failure reporting; do not silently leave an invisible full-window input blocker. Rounded shadows outside the region may be clipped; verify actual visuals later.

1. Implement a dedicated native searchbar module for window lifecycle, work-area geometry, layout/lock/focus/map events and bounded region input. Restrict navigation to the same local origins as the main window. Benchmark mode creates no overlay or shortcuts.
2. Extend host shortcut ownership to transactional named capture/overlay bindings, reject duplicate/conflicting accelerators, and keep previous registration on failure. Apply/rollback overlay settings with existing persistence. Expose searchbar-only window operations and validate open-in-app routes.
3. Add optional rectangle reporting to the incumbent frontend, queue/coalesce DOM updates, subscribe before initial readiness and retain Electron behavior. Relay parsed live events/recent/state to the overlay without starting another log bridge.
4. Source review; formatting, TypeScript/lint, both frontend builds and native compilation/Clippy. No tests, game/process access or actual shortcut registration during verification. Runtime focus, mixed-DPI geometry, transparency/click-through, multi-monitor disconnect, hide/close/restart and hotkey coexistence remain acceptance gates until observed.

## Implementation and source limits

`searchbar.rs` now owns the window, placement, ready/mask handshake, locked state and window events. Geometry and regions are bounded to 128 rectangles and 16384 CSS units; physical placement clamps to monitor work areas. DPI changes hide until a fresh mask arrives. Monitor disconnect is re-clamped on the next geometry/hotkey command, since no monitor-disconnect event was added. Regions use top-level `data-solid` elements, excluding nested descendants already covered by a solid parent. Region ownership follows Microsoft's [SetWindowRgn contract](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowrgn).

The pinned Tao visibility/focus implementation cannot express inactive showing while maintaining its visibility flag through the available public Tauri API. Windows showing/hiding therefore uses `ShowWindow` on the overlay's own HWND (SW_SHOWNOACTIVATE/SW_HIDE); explicit search activation uses `SetForegroundWindow` on that same HWND and reports refusal. Lock style changes restore the intended inactive visibility. Escape hides then restores the desired inactive visibility to release focus. No external window handles, hooks, game process or input injection are used. See Microsoft's [ShowWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-showwindow) and [SetForegroundWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow) contracts; actual foreground behavior remains unverified.

Shortcut registration now validates all capture/overlay bindings together, rejects duplicates and reserves replacements before unregistering old keys. Shared keys can be reassigned without re-registering. Failure reports include rollback failures. Host settings serialize overlay startup/application and private anchor persistence; main-thread close handling avoids waiting on the settings mutex. Main close with minimize-to-tray disabled explicitly exits the app. Searchbar close hides it; tray entries provide show/hide and lock/unlock recovery.

Renderer commands are ordered with at most 32 waiting jobs; adjacent movement deltas coalesce and size/mask updates replace queued values. The mask hook admits one geometry job at a time, uses event-driven observers plus frames for visible changes, and flushes initial/DPI masks without a frame so a hidden WebView cannot deadlock startup. A geometry generation prevents an older in-flight completion from suppressing the next DPI mask. Subscription readiness handles React cleanup, including StrictMode. The searchbar receives bounded recent events and coalesced state from the main log parser. Known packs can be installed from either trusted application window, preserving first-map resource loading; benchmark installation remains blocked.

Source review found discarded lock-state responses, an unbounded movement queue and focus/visibility mismatches; those were fixed. The earlier review concern about main-window close was withdrawn after inspecting the existing explicit exit branch. Native event names for position, pack progress and wipe now use the hyphen convention expected by the Tauri subscription adapter; the desktop API's logical channel names remain unchanged.

No tests, OS shortcut/autostart changes, window launch, actual clicks/focus or game files were used during implementation. Source/build evidence cannot establish runtime overlay parity or performance.

Verification checkpoint: TypeScript, clean lint, both frontend builds, formatting, strict custom-protocol Clippy, embedded native development build and whitespace checks passed. The source UI detector reported no findings. Follow-up review confirmed own-HWND native hiding for all five overlay hide paths. Source references and successful builds do not establish actual Windows focus/click-through behavior; those gates remain open.
