# Signed updater artifact preparation

Goal: make the fork's updater channel files reviewable locally from a real signed native installer, without publishing or inventing signing material.

`npm run build:tauri:staged` is an explicit wrapper around the existing assets/notices/native build pipeline. It requires TC_STAGED_UPDATE_ENDPOINT, TC_STAGED_UPDATE_PUBLIC_KEY and TAURI_SIGNING_PRIVATE_KEY in the environment, adds the optional updater feature and preview UI, and applies tauri.updater.conf.json (createUpdaterArtifacts=true). The install switch remains separately explicit. Signing material is inherited by the existing tooling; it is never printed, passed as a command argument or written by the wrapper. Normal/offline staging commands and manual release workflow remain unchanged. This signed command currently builds the normal NSIS bootstrapper variant.

`npm run updates:prepare -- --artifact <native-exe> --public-key <public-key-file> --url <published-asset-HTTPS-URL> --out <new-directory> [--notes <UTF-8-file>]` runs an optional Rust packaging binary, not an application or installer. It reads the adjacent `<native-exe>.sig`. Inputs are regular files with byte limits; the artifact is capped at 512 MiB. The filename derives from the embedded native product config and Cargo version and must match the x64 fork installer; config/Cargo identity/version drift is rejected. URL filename must match, with HTTPS/no credential/query/fragment and fork-only GitHub paths. Custom-domain ownership is still the release operator's responsibility.

Before any output directory is created, verify artifact and trusted-comment signatures, require the signed version to match this package, and parse the generated static manifest with the actual updater RemoteRelease schema/target accessors. The same pure verification module is used by the native downloader/installer. No private key is needed by the preparation tool; malformed/private-key-shaped public-key input is rejected without printing its content.

Successful preparation writes verified in-memory bytes (not a later mutable source-file copy), signature, latest.json and release-evidence.json to a unique incomplete staging directory, flushes each file and finalizes it into the new output directory. Existing output paths, including dangling symlinks, are refused. Failures after staging starts retain incomplete output and never delete source files. Evidence includes target/version/length/SHA-256 and verified signature/version status, with published=false. Nothing uploads files or contacts the URL. Prefer an ignored directory below target/ for prepared outputs; review them before any separately authorized publication.

The intended platform is windows-x86_64. Installer filename matching does not independently prove its architecture, product identity or coexistence at runtime. The tool does not certify Authenticode, licensing rights or installer behavior. Public manifest fields are not themselves signed; pinned artifact signatures and signed-version binding remain authoritative. A newer release version must be coordinated across package/Cargo/Tauri metadata before a real update can be offered. The signing CLI must include version metadata; older unversioned signatures are rejected.

Default-run is set explicitly to the existing app binary because the package now has an additional optional tool binary. Updater artifact/manifest generation has not been exercised: no signing key or signed .sig was supplied, and no key/fixture was created. The packaging wrapper is not executed, no installer is run and no publication occurs. No tests are created or run.

Verification on 2026-11-01: staged/default strict Clippy and native builds (24.66s/20.68s), final packaging-tool binary build (19.62s), clean oxlint, wrapper syntax check, build JSON parsing, formatting and whitespace checks exited 0. The final prepare-update.exe exists locally (2,108,928 bytes); it was not executed. Source review traced signature/version verification shared with the app, actual RemoteRelease schema parsing before output creation, native metadata/URL filename binding, bounded regular-file reads, immutable-byte copies, fresh output paths and no network/signing/publication calls. The installed Tauri config schema includes createUpdaterArtifacts. Runtime signed packaging, valid/invalid-signature cases, output lifecycle and channel/update/recovery acceptance remain open; existing installer artifacts were not refreshed.
