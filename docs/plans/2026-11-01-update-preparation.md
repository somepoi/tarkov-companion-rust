# Native update preparation and IO admission

Goal: prepare a recoverable update boundary that cannot overlap admitted native writes, without enabling installer execution.

Add a shared process-local IO gate. Native inventory calls retain a shared lease through actual SQLite actor completion; full backup commands, screenshot archival/capture, settings/picked-folder changes, daily backup writes, pack installation, hotkey tasks and position-shot recycling retain their leases through the blocking operation. Read-only log/pack/screenshot transport remains available. Leases live inside actual blocking jobs, so a dropped caller does not falsely make the application idle. The gate has no timers/polling and normal operation does not wait for a writer.

The opt-in updater preview can now request a recovery copy after downloading a candidate and explicitly confirming saved drafts. Native preparation requires the main window, non-benchmark mode, saved-draft assertion and a fresh native candidate ID. It acquires the updater operation guard and an exclusive gate nonblockingly; active jobs cause a clear retry error. The exclusive lease prevents admission of protected new operations while the existing full snapshot-bound backup creator runs through its internal SQLite actor access. This privileged helper does not recursively take a shared lease. All leases release on error/success; the updater/exclusive guards live with actual backup work even if the caller goes away.

The native preparation command saves a recovery point, not an installation authorization. Its candidate check is not proof that a staged file is still valid: installer implementation must reacquire the gate, reverify current file/signature/version and manage shutdown/outcome. The copy is separately captured renderer state plus a transactional SQLite snapshot, with the incumbent warning about keeping the app idle; frontend localStorage across windows is not globally frozen by this native gate. Native startup initialization and ordinary readonly watcher transport are not claimed to be globally stopped. Background position recycling skipped during exclusive preparation leaves source files intact.

No installer call/restart, automatic data conversion, cleanup, updateMode change or production update enablement is added. Return installable=false and retain the completed recovery bundle in full-backups. Preparing again after later edits requires a new recovery point. No secret/key/channel data or external requests are introduced by this step.
