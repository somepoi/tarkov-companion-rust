# Bounded screenshot admission before browser decode

Goal: enforce the audit's image budget before allocating a full browser bitmap or frontend-to-native byte payload. The Rust archive already reads dimensions before storing a screenshot, but OCR, scanner matching, correction learning and several archived-image readers decoded browser images before checking dimensions.

Implementation: inspect at most the first 1 MiB of a nonempty Blob capped at 64 MiB. Read advertised PNG/JPEG/WebP/BMP/GIF dimensions and enforce the incumbent 40-million-pixel geometry budget. JPEG frame metadata beyond that bounded prefix and unsupported/unknown formats produce an explicit error. Accept dimensions from bytes, never from MIME or a filename. The browser decoder still validates actual contents and its output dimensions are checked again, with bitmap closure on rejection. JPEG EXIF orientation can swap dimensions; equality is deliberately not required. Raster metadata admission does not establish a strict bound on every codec's internal allocation or animated-frame memory.

Route scanner, name/quantity OCR, correction learning, source review, view alignment and Stash Manager bitmap reads through the shared decoder. Optional cancellation is checked before header read, before decode and after decode; browser decoding itself cannot be forcibly interrupted. Check archive uploads before image.arrayBuffer, retaining native checks independently. The legacy scanner validates before creating its preview URL and invalidates old result generations across image changes; rejected images clear old rows/results instead of leaving them applicable to a new image. Native archived/capture paths remain bounded independently.

No algorithm, threshold, physical inventory or schema change. Valid raster images still require browser decode; malformed compressed content is not certified by this lightweight header reader. The format/metadata limits are visible admission rules, not a measured memory or accuracy improvement.
